## 9/12 (금) - 팀 개발 컨벤션 정립 및 중간발표 준비

### 오늘 한 일
팀 개발을 위한 코드 관리 방식을 논의하여 컨벤션을 정립하고, 중간발표용 PPT 자료를 제작했다.

### 팀 개발 컨벤션 결정사항

**1. 타입 관리 방식**
- `src/types/` 폴더에서 공통 관리
- 도메인별로 파일 분리 (auth.ts, game.ts, carbon.ts)
- 타입 네이밍: PascalCase 사용

**2. 컴포넌트 재사용 전략**
- 공통 컴포넌트: Header, BottomNavigation
- `src/components/common/` 폴더에서 관리
- Props 인터페이스는 컴포넌트와 동일 파일에 정의

**3. 스타일 관리**
- `src/styles/` 폴더에서 공통 스타일 관리
- 색상 팔레트, 폰트, 공통 스타일 상수화
- 각 컴포넌트별 스타일은 별도 분리

**4. 목업 데이터 관리**
- `src/data/mock/` 폴더에서 관리
- 백엔드 API 완성 전까지 개발 진행용
- 실제 API 구조와 일치하도록 설계

### 중간발표 자료 제작
프로젝트 진행 현황과 기술적 성과를 정리하여 발표 자료 완성

### 배운 점
팀 개발에서는 개인의 코딩 스타일보다 일관성이 더 중요하다. 초기에 컨벤션을 명확히 정하면 나중에 코드 통합 시 충돌을 줄일 수 있다. 공통 스타일과 타입 관리는 개발 효율성을 크게 향상시킨다.
