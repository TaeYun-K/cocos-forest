# 스프링(Spring) vs 스프링부트(Spring Boot)

## 1. 개념

- **스프링 (Spring Framework)**

  - 자바 기반의 엔터프라이즈 애플리케이션 개발을 위한 프레임워크
  - DI(의존성 주입), AOP, 트랜잭션 관리 등 핵심 기능 제공
  - 설정이 복잡하고 초기 환경 구성에 많은 시간이 필요

- **스프링부트 (Spring Boot)**
  - 스프링을 더 쉽게 사용하기 위한 확장 프레임워크
  - 자동 설정(Auto Configuration), 내장 서버, 스타터 의존성 제공
  - 최소한의 설정으로 빠른 개발 가능

---

## 2. 주요 차이점

| 구분              | Spring                                   | Spring Boot                         |
| ----------------- | ---------------------------------------- | ----------------------------------- |
| **설정 방식**     | XML/자바 기반 수동 설정                  | Auto Configuration, Starter 활용    |
| **환경 구성**     | 복잡, 초기 설정 많음                     | 최소 설정으로 시작 가능             |
| **내장 서버**     | 없음 (Tomcat, Jetty 등을 별도로 배포)    | Tomcat/Jetty 내장 → `jar` 실행 가능 |
| **프로젝트 구조** | 자유도가 높음 (직접 구조 설계)           | 기본 구조 권장 → 빠른 개발 지원     |
| **빌드/패키징**   | 주로 WAR 패키징                          | JAR 패키징 기본, 실행형 앱          |
| **목표**          | 범용적이고 확장성 있는 엔터프라이즈 개발 | 생산성과 빠른 프로토타입 개발       |

---

## 3. 정리

- **Spring**: 자유도와 유연성이 크지만, 설정이 복잡하고 진입장벽이 높음
- **Spring Boot**: 스프링을 쉽게 사용할 수 있도록 만들어진 프레임워크로, 빠른 개발과 배포에 강점
- → **관계**: "스프링부트는 스프링 위에서 동작하는 보조 도구"
